## 目标场景与核心问题

长时算力任务（数值模拟、大模型训练、大规模批处理）的**典型故障不是崩溃，是"进程活着却没有进度"**。

现有运维只做心跳级检查——进程在、CPU 高、端口通就算健康。但这类任务的日志静默本是常态
（数值模式按输出间隔写、训练按 step 写、下载任务干脆不写），
于是"日志不动"同时对应"一切正常"和"已经死了"，**单信号无法区分**。

真实代价：一次三模式耦合作业跑满两小时、模式正常结束，却一个重启文件都没产出；
操作者读模式源码正确定位了根因、应用了修复，第二次仍在凌晨失败。
**两夜共烧掉约 4.5 小时的 160 核机时。代价不在诊断能力，在于验证一个假设要等两小时，且结果在无人值守时揭晓。**

## 方案概述

以 **AgentTeams** 为多 Agent 协同基点，构建从发现到沉淀的完整闭环，
把关键能力沉淀为**八个可复用 Skill**，领域差异收敛到**适配器配置**。

核心判据：**资源占用只有在「资源画像符合该 workload 的预期」时才算进展证据。**
日志进度行与产物文件无条件算；CPU / GPU 要看画像 —— GPU 训练里
"CPU 打满而 GPU 闲置"不算进展，反而是退化路径的指征。
任一算数的信号有变化即判"在推进"，全部静止且超过该 workload 阈值才判卡死。

并且**日志"在长"不等于"有进度"**：需匹配该 workload 的进度行，
一个疯狂刷同一行错误的作业，日志持续增长但进度行为零，判定为卡死。

这条判据是被自己的实测推翻后改的：原设计把三类信号对等 OR，
在 GPU 退化路径上全程漏报（见 evidence/measure-06）。

## 多 Agent 架构

| Agent | 职责 | 风险上限 |
|---|---|---|
| Sentinel 哨兵 | 多信号采集与进度语义判定 | L0 只读 |
| Triage 诊断 | 故障归类、根因候选、证据分级 | L0 只读 |
| Planner 规划 | 恢复方案 + 风险分级 + 回滚点 | L0 只出方案 |
| Executor 执行 | 护栏内执行，幂等键 + 审计 | L1 自动 / L2 审批 |
| Verifier 验证 | 校验续跑后时间轴与结果连续性 | L0 只读 |
| Curator 沉淀 | 复盘写回 Runbook，提新判据 PR | L1 需人工 review |

**动作强制落在 L0–L3 分级内**：只读自动 / 白名单低风险自动 / 中风险必须人工审批 /
高风险拒绝自动执行只输出方案。

## 关键 Skill 与工具链

八个 Skill：`progress-probe`、`crash-triage`、`restart-planner`、`resource-guard`、
`safe-kill`、`config-precheck`、`runbook-rag`、`postmortem-write`。

工具链：AgentTeams v1.2.2（必选，Apache-2.0）+ Higress 网关（凭证隔离）+
自研 `cluster-mcp-server`（MCP over stdio，4 个只读工具，纯标准库零依赖）+
7 份 workload 适配器配置。

## Demo 运行结果

| 实测 | 结果 |
|---|---|
| `config-precheck` 四配置状态 | 三次失败中两次的根因零成本检出；两份真实配置**零误报** |
| GPU 退化路径卡死（4090） | 真造卡死并回放：**旧判据全程漏报**，修复后 909s（20s 采样）/ 318s（10s 采样）发现 |
| Agent 边界验证 | 材料不可达时经 6 轮排查后如实报告，**全程未编造分析** |
| 三 Agent 闭环 | 哨兵→诊断→规划走通，诊断发现了一条此前无人注意的可观察差异 |
| MCP 安全边界 | 越权路径与命令注入串均被拒绝并入审计 |
| 可观测采集 | 56 span，来自框架自带治理审计库；**采出 39% 的 Bash 调用处于无沙箱状态**（主动报告） |

三条命令即可复现全部结果，纯标准库、不调模型。

## 业务价值与可复制性

**已验证**：气象海洋耦合（WRF / ROMS / SWAN）、GPU 训练（PyTorch）。
**设计覆盖但未实测**：数据下载与批处理流水线。
**仅结构相似性推断**：CAE / EDA 仿真、生信流程。

可迁移性的机制保证是**领域差异全部收敛在 `adapters/*.json`**
（进度行正则、产物 glob、两个阈值、restart 语义），接新场景只写一份 JSON，
Agent 定义与 Skill 规格均不改动。每次判定的返回里都带 `adapter` 字段标明用了哪份配置。

行业规模参照：Meta 训练 LLaMA 3 在 54 天内被打断 419 次；
微软报告平均每 45 分钟一次故障；字节跳动每天至少一次。
