# runbook rag

> 规格草案。字段按赛道一参赛手册附录 B「Skill 清单模板」组织，
> 完整输入输出 Schema、失败处理与判据表在复赛阶段补齐。

## 使用场景

检索团队 Runbook、历史事故复盘、工作日志与官方文档，为诊断和恢复规划提供有依据的领域知识。检索不到强相关内容时明确返回'无匹配'，不用通用知识硬答。

## 输入 / 输出

待定稿。

## 调用条件

待定稿。

## 依赖工具 / 系统

集群适配器（MCP 或等价集成契约）。凭证由网关注入，Skill 不持有真实凭证。

## 失败处理

统一原则：**证据不足时输出"缺什么"，不猜、不编造结论。**

## 权限与安全

风险等级 L0。分级定义见 [README](../../README.md#安全分级)。

## 复用价值

领域差异收敛到 adapter 配置，Skill 逻辑与 workload 无关。

## 版本与演进

**知识库内容**与**检索策略**分开计版：

- 知识库随复盘持续增长，按快照日期标识，支持回放到某个历史时点的知识状态
  （用于复现「当时的 Agent 为什么没查到这条」）
- 检索策略（切分方式、embedding 模型、重排规则、top-k）单独计版，
  变更后须在同一评估集上复测

更换 embedding 模型属于 major —— 向量空间变了，全库需要重建。

## 能力评估

| 指标 | 说明 |
|---|---|
| 命中相关性 | 对标注好的「问题 → 应命中的 Runbook 条目」评估集算召回 |
| **「无匹配」正确率**（首要） | 知识库里确实没有相关内容时，是否老实返回「无匹配」 |
| 引用可追溯率 | 返回的每一条 passage 是否都能定位到源文档与位置 |

第二项是这个 Skill 的核心风险控制点。检索增强最危险的失败模式不是查不到，
而是**查不到却用通用知识编一段看起来专业的答案** —— 在运维场景里这会直接导向错误操作。

因此评估集必须包含一批**故意问知识库里没有的问题**的负样本，
这类样本上返回「无匹配」记为成功，返回任何具体建议记为失败。
