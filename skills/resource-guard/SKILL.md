# resource guard

> 规格草案。字段按赛道一参赛手册附录 B「Skill 清单模板」组织，
> 完整输入输出 Schema、失败处理与判据表在复赛阶段补齐。

## 使用场景

提交前检查全局资源账是否超订，运行中检测慢节点与资源倾斜。

## 输入 / 输出

待定稿。

## 调用条件

待定稿。

## 依赖工具 / 系统

集群适配器（MCP 或等价集成契约）。凭证由网关注入，Skill 不持有真实凭证。

## 失败处理

统一原则：**证据不足时输出"缺什么"，不猜、不编造结论。**

## 权限与安全

风险等级 L0。分级定义见 [README](../../README.md#安全分级)。

## 复用价值

领域差异收敛到 adapter 配置，Skill 逻辑与 workload 无关。

## 版本与演进

资源规则（安全余量、慢节点判定的离群阈值、每机可并行作业上限）是**配置**，
随集群变化频繁调整，不计入 Skill 版本。Skill 本体只在判定算法或输出 Schema 变更时升版。

新接入一台机器 = 新增一份机器画像配置，不改 Skill。

## 能力评估

用历史超订事故回放：给定当时的机器状态与提交请求，验证是否会拦下。

| 指标 | 说明 |
|---|---|
| 超订拦截率 | 历史上真实触发过资源竞争故障的提交，应被全部拦下 |
| **过度保守率**（反指标） | 实际可以安全运行的提交被拦下的比例。这项过高会让人绕过检查，等于没有 |
| 慢节点识别 | 与事后确认的问题节点比对 |

两个指标必须一起看。只压超订拦截率会得到一个「什么都不让跑」的 Skill，
在真实团队里的下场是被 `--force` 绕过。
