# crash triage

> 规格草案。字段按赛道一参赛手册附录 B「Skill 清单模板」组织，
> 完整输入输出 Schema、失败处理与判据表在复赛阶段补齐。

## 使用场景

作业已停止时判断为什么停。故障类目：数值发散、内存耗尽、并行框架异常中止、依赖库与环境问题、磁盘写满、节点掉线、配置错误，以及'良性退出'（退出码非零但属正常终止）。

## 输入 / 输出

待定稿。

## 调用条件

待定稿。

## 依赖工具 / 系统

集群适配器（MCP 或等价集成契约）。凭证由网关注入，Skill 不持有真实凭证。

## 失败处理

统一原则：**证据不足时输出"缺什么"，不猜、不编造结论。**

## 权限与安全

风险等级 L0。分级定义见 [README](../../README.md#安全分级)。

## 复用价值

领域差异收敛到 adapter 配置，Skill 逻辑与 workload 无关。

## 版本与演进

**故障类目表与判据是数据，不是代码**，与 Skill 本体分开计版。

| 变更 | 版本位 |
|---|---|
| 新增故障类目 / 新增判据 | 类目表 minor（Skill 本体不动） |
| 改变已有类目的语义边界 | 类目表 major —— 会让历史复盘的归类失效 |
| 输出 Schema 变更 | Skill 本体 major |
| 误报排除规则调整（如把某种日志模式加入白名单） | 类目表 patch |

新判据的来源是 Curator 的复盘产出，走 PR + review 入库，禁止自动写入 ——
**一次错误归因如果被固化成判据，之后每次都会错。**

## 能力评估

评估集 = 历史故障归档，每条含：日志片段 + 退出码 + 真实根因类目。

| 指标 | 说明 | 目标 |
|---|---|---|
| 归类准确率 | 输出类目与真值一致 | 高 |
| **幻觉率**（首要反指标） | 在证据不足时仍给出具体根因的比例 | **趋近 0** |
| `UNKNOWN` 质量 | 判 `UNKNOWN` 时，给出的「缺什么证据」清单是否正确 | 判 UNKNOWN 且清单正确**计为成功**，不计为失败 |
| 良性退出识别率 | 把 `rc=1` + IEEE 浮点标志正确识别为良性而非故障 | 高（见证据案例 01） |

评估方式为**规则评估 + LLM-as-Judge 双轨**：
规则评估判类目是否命中；LLM-as-Judge 只判一件事 ——
**「这个根因结论有没有挂上具体的证据引用」**，没有引用的结论一律判为幻觉。

这个设计是刻意的：宁可让它频繁说「我不知道，我需要这几样证据」，
也不要它说一个听起来很合理但没有依据的根因。运维场景里，一个自信的错误结论比沉默贵得多。
