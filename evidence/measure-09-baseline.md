## 为什么要做

在这份之前，我们能说的只有"本方案在自己的数据上表现如何"。
**没有基线，"我们的判定更好"就是不可证伪的** —— 评委完全有理由问一句：
"这些数字很好，但一个 `ps` 加一行 `grep` 是不是也能做到？"

这份文档回答这个问题：把本方案和**五种常见做法**放在**同一批真实数据**上跑。

## 六种判据

| | 判据 | 谁在用 |
|---|---|---|
| B1 | 进程存活 | 绝大多数心跳监控、`systemd` 存活探针、K8s liveness probe |
| B2 | CPU 占用 > 50% | "看着 CPU 满就是在算" |
| B3 | 日志文件 size 增长 | `watch ls -l`、日志大小告警 |
| B4 | 日志新增内容里有进度行 | 稍讲究的做法：`tail -f \| grep` |
| B5 | 三信号对等 OR | **本项目 v0.1.0** —— 日志/产物/CPU 任一有变化即 RUNNING |
| B6 | 进展/存活分层 | **本项目 v0.2.0**（当前） |

B5 单独列出来是有意的：**那是我们自己被实测证伪的上一版**，
把它放进对照里，才对得起"这份评估是诚实的"这句话。

## 五个数据集

| 数据集 | 真值 | 来源 |
|---|---|---|
| 正 A · GPU 退化路径卡死，20s 采样 | **应当告警** | 4090 实测（[measure-06](measure-06-gpu-stall.md)） |
| 正 B · GPU 退化路径卡死，10s 采样 | **应当告警** | 4090 实测（[measure-07](measure-07-sampling-rate.md)） |
| 负 C · GPU 训练 150 分钟，日志稀疏 | **不应告警** | 4090 实测，训练**正常结束**（`DONE step 1479889 ckpt 4`） |
| 负 A · COAWST 三模式耦合 33.79h | **不应告警** | 真实科研运行，跑到 `SUCCESS COMPLETE` |
| 负 B · 18 GB 数据集下载 4.29h | **不应告警** | 真实下载，完整完成 |

正样本的真值来自"我们亲手造的卡死"，负样本的真值来自"作业自己跑到了成功结束"。
两侧的真值都不靠人工标注。

## 每一种做法具体栽在哪

### B1 进程存活、B2 CPU 占用 —— 从不误报，但两次真卡死全漏

这两条正是现状。它们在三个负样本上表现完美（0 误报），
所以在日常里显得"很稳"——**代价是对这类故障完全失明**。

GPU 退化路径里进程一直是活的、CPU 一直是 100%，
心跳监控看到的就是一条平直的绿线。这就是 README 开篇那句话的实证。

### B3 日志 size、B4 日志进度行 —— 抓得住卡死，却在真实训练上误报近 200 次

这两条比心跳讲究，正 A 上确实抓到了（905 秒）。但：

- **正 B 漏报**：那次卡死只持续 600 秒，而它们只能用通用的 900 秒阈值，
  等不到就结束了。B6 因为识别出了退化画像（CPU 打满 + GPU 闲置 + GPU 曾经忙过），
  可以用更短的 300 秒阈值，所以 308 秒就报了。
- **负 C 误报 190 / 192 次**：那是一次**真实跑完的训练**，
  日志 20 分钟才写一行、checkpoint 30 分钟才存一个，
  日志最长连续静默 **18.2 分钟**、产物最长静默 **27.5 分钟**，
  都超过 15 分钟阈值。于是只看日志的做法在一次正常训练里叫了近 200 次。

**这正是"日志静默是常态、不是异常"的量化证明。**
按 10 秒采样、一次训练 150 分钟算，这样的告警系统一周内必然被关掉。

### B5 三信号对等 OR —— 我们自己的上一版，两次卡死全漏

CPU 占用被当作与日志、产物完全对等的一票。GPU 卡死时 CPU 恰恰打满，
这一票把状态硬拉成 RUNNING。详见 [measure-06](measure-06-gpu-stall.md)。

它在三个负样本上都是 0 误报——**低误报不代表判据是对的**，
一个永远说"在跑"的判据误报率也是 0。这正是必须两侧一起看的原因。

### B6 本方案 —— 五个数据集全对

- 两次卡死都发现（905s / 308s）
- 三个真实成功运行（合计 **40.6 小时**）零误报

关键差别在**负 C**：它是唯一能区分 B3/B4 与 B6 的数据集。
B6 在那里没有误报，靠的是 **GPU 忙符合该 workload 的资源画像**这一票——
日志和产物确实都静默了，但 GPU 一直在 61% 上下工作，这就是"在推进"的证据。

## 局限（不隐瞒）

1. **五个数据集里三个来自同一台 4090、同一套训练脚本**，
   COAWST 与下载来自同一集群同一团队。样本多样性不足以谈"泛化"。
2. **两个正样本都是构造的复现**，不是生产事故现场。
3. **基线是我们自己实现的**。B1–B4 按各自最直白的语义实现，
   用的是与 B6 完全相同的阈值与采样序列（见 `baseline_compare.py`，逐条可核）。
   但真实世界的监控系统会有各种额外启发式，本对照不代表任何具体产品。
4. B3/B4 在负 C 上的误报次数（190 / 192）是**告警触发的采样点数**，
   不是"独立告警事件数" —— 实际部署里通常会做去重与静默窗口，
   真实体感次数会低于这个数，但**误报存在**这个结论不受影响。
